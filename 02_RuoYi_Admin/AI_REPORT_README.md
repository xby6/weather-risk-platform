# 算法结果 AI 报告首版

任务结果保存后，后端读取结果快照，统计数据并整理 Prompt，再调用已配置的 LLM，生成结果分析、风险说明、处理建议及数据局限。报告独立于算法任务：报告失败不会把成功任务改为失败，关闭页面后仍继续生成。

## 部署与使用

1. 在应用数据库执行 `ruoyi-fastapi-backend/sql/algorithm_report_20261007.sql`。具备建表权限时，后端也会自动创建缺失的两张表。数据库账户应能读写 `algorithm_report_config`、`algorithm_report`。
2. 重启后端并部署最新前端。后端需能写入 `vf_admin/algorithm_reports`，且能访问选定 LLM 的接口地址。
3. 在已有的 **AI 模型管理** 中配置并启用模型，包括供应商、模型代码、接口地址和 API Key。
4. 在 **任务管理 → AI 报告设置** 中选择默认 LLM，可补充单位、阈值或分析重点，并开启自动生成。修改全局设置需要已有的 `ai:model:edit` 权限。
5. 在任务行点击 **AI 报告**，查看历史报告、手动生成、重新生成新版本、重试失败报告或下载 Markdown。已登录用户的任务和报告可见范围沿用现有共享任务管理方式。

自动生成默认关闭，只处理开启后新运行并成功的任务；旧任务可手动生成。后台每 10 秒检查新运行任务，即使前端关闭也会获取算法任务状态并排队。同一次运行的重复触发返回同一份报告；重新运行任务或点击“重新生成新版本”会保留旧报告并生成新报告。

## 数据与生成流程

- 支持结构化 JSON 结果，以及已缓存的 Excel、CSV、JSON 结果文件。统计使用完整表格行，不使用前端截断的预览。Excel 优先分析未来故障预测、总体统计、每折结果、每个样本预测结果、概率等级统计等工作表。
- 每份报告保存任务及算法信息、原始结果快照、结果文件副本、统计依据、实际用户 Prompt、模板版本、无密钥的模型信息和生成内容。任务重跑覆盖原文件时，旧报告仍使用自己的文件副本。
- 后端先计算样本数、有效值、缺失值、最小值、最大值、均值、风险分布和时间范围，再交给模型解释。依据编号 `[S1]` 等可在页面展开查看。
- API Key 由既有模型配置解密后仅用于后端请求，不返回报告页面，不写入 Prompt。常见密钥字段及内部路径字段会从发送数据中移除。
- LLM 返回固定 JSON 结构，后端校验章节、内容长度和数据依据引用，前端以文本渲染，下载内容附带系统统计与依据。

后台队列持久化到数据库，使用 5 分钟租约避免多个进程同时处理一份报告，并在重启后恢复过期任务。单次 LLM 请求超时 120 秒，整次处理超时 240 秒。失败最多自动尝试 3 次，前两次分别等待 15、30 秒；最终失败可手动重试。首版每个后端进程串行生成报告。

## 首版边界

- 当前是单次任务结果报告，检测/预测时段使用该任务输入和结果中的时间信息；尚未实现跨任务的日报、周报或自选时段汇总。
- 单个文件上限 128 MB，Excel 最多分析 6 个工作表，每表最多统计 40 个非敏感字段，并提供最多 10 条代表性记录。风险分布最多展示 30 类。复杂嵌套 JSON 提供有界样本，后续可增加专用适配器。
- 证据 JSON 超过 40,000 字符时移除代表性记录；仍超过 50,000 字符则报告失败并提示增加专用适配器。补充要求最多 4,000 字符。
- 未缓存的文件或未支持的文件格式，仅在算法返回 `summary` 时分析摘要，否则明确失败。解析 `.xls` 需要部署环境安装对应的 Pandas Excel 引擎。
- 模型输出校验能检查结构和引用，不能保证每个结论或数字的语义正确。报告应结合系统统计复核；缺少单位、阈值、实际故障反馈时，模型会被要求写明缺失信息，区分预测与已发生故障。
- 报告及文件副本在删除任务后仍保留，当前不提供报告清理或保留期限设置。备份时同时备份两张报告表及 `vf_admin/algorithm_reports`。

## 验证

在 `ruoyi-fastapi-backend` 下执行：

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -p 'test_algorithm*.py' -v
```

在 `ruoyi-fastapi-frontend` 下执行：

```powershell
npm run test:tasks
node --max-old-space-size=8192 node_modules/vite/bin/vite.js build
```

报告测试使用独立内存数据库和模拟 HTTP LLM，覆盖完整文件统计、快照保留、去重、重跑、失败重试、租约恢复、自动排队、接口鉴权、下载，以及已有模型工厂的实际请求适配路径。不会调用真实付费接口或修改项目数据库；部署后仍需用实际配置模型做一次联调。
